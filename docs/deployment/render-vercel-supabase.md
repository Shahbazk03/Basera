# Deploying to Supabase + Render + Vercel

| Part | Service | Region |
| --- | --- | --- |
| PostgreSQL (with PostGIS) and photo/document storage | **Supabase** | Southeast Asia (Singapore) |
| Backend API, background jobs, queue (Redis-compatible Key Value) | **Render** — [`render.yaml`](../../render.yaml) | Singapore |
| Website (`apps/web`) and business console (`apps/console`) | **Vercel** — two projects, see `apps/*/vercel.json` | Singapore (`sin1`) |

Everything sits in one region because the API makes many database queries per page.
Never put any of the values below in GitHub — they go into the Supabase, Render and Vercel dashboards only.

## 1. Supabase — database

1. supabase.com → **New project** → region **Southeast Asia (Singapore)** → generate a database password (letters and numbers only is easiest) and keep it in a password manager. Use the **Pro** plan for the live site.
2. **Connect** (top bar) → **Connection string → URI → Session pooler** (port 5432). Replace `[YOUR-PASSWORD]` and add `?sslmode=require`:
   ```
   postgresql://postgres.<project-ref>:<password>@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres?sslmode=require
   ```
   This is **`DATABASE_URL`**. (Not "Direct connection" — it is IPv6-only and Render cannot reach it. Not the transaction pooler on 6543.)
3. Optional, recommended: **Project Settings → Database → SSL Configuration → Download certificate**. Paste the file's text into Render as **`DATABASE_SSL_CA`** to have the API verify the server certificate. Without it the connection is still encrypted.

Tables, the PostGIS/pg_trgm extensions and reference data (roles, permissions, locations, property types) are created automatically when the backend starts.

## 2. Supabase — photo & document storage (S3-compatible)

1. **Storage → New bucket** `basera-public` — **Public bucket: on** (listing and project photos).
2. **Storage → New bucket** `basera-private` — **Public bucket: off** (documents, receipts; served with short-lived signed links).
3. **Storage → Settings → S3 Connection** → enable it, note the **Endpoint** and **Region**, then **New access key** → copy the **Access key ID** and **Secret access key** (shown once).

| Render variable | Value |
| --- | --- |
| `S3_ENDPOINT` | the endpoint, e.g. `https://<project-ref>.supabase.co/storage/v1/s3` |
| `S3_REGION` | the region shown, e.g. `ap-southeast-1` |
| `S3_BUCKET_PUBLIC` / `S3_BUCKET_PRIVATE` | `basera-public` / `basera-private` |
| `S3_PUBLIC_BASE_URL` | `https://<project-ref>.supabase.co/storage/v1/object/public/basera-public` |
| `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` | the access key |

## 3. Choose the Vercel addresses first

Vercel gives each project `https://<project-name>.vercel.app`. Decide the names now (for example `basera-web` and `basera-console`) because Render needs the addresses. If a name is taken, use the address Vercel actually gives you everywhere below.

## 4. Render — backend

1. Render → **New → Blueprint** → connect GitHub → repository **Basera** → Render reads `render.yaml` and proposes **basera-api** (web service, Docker) and **basera-redis** (Key Value).
2. Fill in the values it asks for:

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | from step 1 |
| `WEB_PUBLIC_URL` | `https://basera-web.vercel.app` |
| `CONSOLE_PUBLIC_URL` | `https://basera-console.vercel.app` |
| `PLATFORM_ROOT_DOMAIN` | `basera-web.vercel.app` (your own domain later) |
| `PLATFORM_MAIN_HOSTS` | `basera-web.vercel.app` |
| `S3_*` | from step 2 |
| `ADMIN_EMAIL`, `ADMIN_NAME`, `ADMIN_PASSWORD` | your first Super Admin (password ≥ 10 characters with a letter and a number) |

   Secrets (`JWT_ACCESS_SECRET`, `DATA_ENCRYPTION_KEY`, `FILE_URL_SIGNING_SECRET`) are generated by Render — never change `DATA_ENCRYPTION_KEY` afterwards (it encrypts bank/PAN details).
3. **Apply**. The first build takes a few minutes; the logs show `[release] Applying database migrations`, `Seed complete.`, `Super Admin ready` and `API listening`.
4. Check `https://basera-api.onrender.com/api/v1/health/ready` (use your service's address) → `"status":"ready"`.

Later, in **basera-api → Environment**, add email so password resets and notifications are delivered: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM` (any SMTP provider). Until then messages are recorded as "not configured".

The admin variables can stay: an existing Super Admin is never changed on restart (set `ADMIN_RESET_PASSWORD=true` once to reset that password).

## 5. Vercel — website and console

Vercel → **Add New → Project** → import **Shahbazk03/Basera** — do this twice:

| | Website | Console |
| --- | --- | --- |
| Project name | `basera-web` | `basera-console` |
| Root Directory | `apps/web` | `apps/console` |
| `API_INTERNAL_URL` | `https://basera-api.onrender.com` | same |
| `WEB_PUBLIC_URL` | `https://basera-web.vercel.app` | same |
| `CONSOLE_PUBLIC_URL` / `NEXT_PUBLIC_CONSOLE_URL` | `https://basera-console.vercel.app` | — |
| `NEXT_PUBLIC_WEB_URL` | — | `https://basera-web.vercel.app` |
| `PLATFORM_ROOT_DOMAIN` / `PLATFORM_MAIN_HOSTS` | `basera-web.vercel.app` | — |
| `APP_ENV` | — | `production` |
| `S3_PUBLIC_BASE_URL` | same as Render | same as Render |

Build and install commands come from each app's `vercel.json` (it builds the shared package first). Environment variables are read at build time — **redeploy after changing them**.

## 6. First sign-in and checks

1. Open `https://basera-console.vercel.app/login` and sign in with the Super Admin from step 4.
2. **Admin → Settings**: brand name, contact details. Add locations and property types if needed.
3. Upload a listing photo larger than 5 MB. Vercel limits request sizes; if this fails, report it — uploads will then be sent directly to storage.
4. Send a test enquiry from the website and see it arrive under **CRM → Leads**.

Project microsites on their own domains need your own domain on Vercel (custom domains cannot use `vercel.app`); this comes later.
